%% =========================== ABSTRACT ================================
\begin{abstract}
House prices shape lending, rates and most families' biggest financial
decision, yet free online valuation tools give a price without a
reason. We build an explainable machine-learning pipeline for Auckland
house prices and ask whether data about a home's surroundings improves
prediction. From 92,010 Auckland Council sales (2024--2026), we use
Splink probabilistic record linkage to give each property a LINZ
coordinate, keep 59,708 market sales, and link 16 external features:
location, 2023 Census and deprivation statistics, flood and noise
exposure, and building activity. Under time-ordered five-fold
cross-validation, adding these features to the same XGBoost model cuts
RMSE from \$343,718 to \$212,678 and MAPE from 19.3\% to 11.0\%. A
paired bootstrap shows the gain is significant, and a two-stage test
shows the external features explain 29.3\% of the error a property-only
model leaves. Three importance methods agree that location drives most
of the gain. XGBoost also beats four other models, including a hedonic
regression (MAPE 15.7\%), and SHAP explains each prediction in dollars.
On 46 recent sales, however, homes.co.nz estimates recorded before each
sale were more accurate (MAPE 6.0\% vs 9.6\%), pointing to the value of
richer property data.
\end{abstract}

\begin{IEEEkeywords}
house price prediction, explainable AI, SHAP, record linkage, Splink,
gradient boosting, hedonic regression, Auckland
\end{IEEEkeywords}

%% ========================= I. INTRODUCTION ===========================
\section{Introduction}\label{sec:intro}

For most New Zealand households, a home is the largest thing they will
ever buy. Its value matters to many people: buyers and sellers use it to
set a price, banks use it to decide how much to lend, and Auckland
Council uses it to set rates. In Auckland, these values are hard to
predict. Homes differ a lot in size, age and condition, and so do the
places they sit in. Some areas are close to the city centre or the coast,
some neighbourhoods are much richer than others, and some homes sit in a
flood plain or under a flight path. A model that only looks at the house
itself will miss a large part of its price.

Free online valuation tools give buyers a number but not a reason. A
buyer cannot see whether an estimate is high because of the house, its
location or something else. This matters when the estimate feeds a
decision worth a million dollars.

Past research has studied this problem from two sides. Hedonic studies
of Auckland have measured the effect of one outside factor at a time,
such as flood risk~\cite{samarasinghe2010}, school
zones~\cite{rehm2008}, leaky-building stigma~\cite{rehm2009} and social
housing~\cite{sequeira2021}. These models are easy to read, but they are
built to explain one effect, not to predict new
sales~\cite{shmueli2010}. Machine learning models predict prices more
accurately~\cite{ceh2018,an2025}, and SHAP~\cite{lundberg2017} can show
which features drive each prediction. However, we found no study that
applies explainable machine learning to Auckland, and few that measure
how much a \emph{combined} set of outside data improves prediction on
sales the model has not seen.

This paper answers two research questions:
\begin{itemize}
  \item \textbf{RQ1:} Does adding Auckland-specific external features
  (location, neighbourhood, hazards and building activity) improve house
  price prediction compared with using only a property's own features?
  \item \textbf{RQ2:} How accurate and interpretable is our explainable
  model compared with a traditional hedonic model and free online
  valuation estimates for the same Auckland properties?
\end{itemize}
We test three hypotheses:
\begin{itemize}
  \item \textbf{H1:} The same XGBoost model predicts sale prices with
  lower error when the external features are added, and the drop in
  error is statistically significant.
  \item \textbf{H2:} The external features contain information that the
  property features do not, so a model that sees \emph{only} external
  features can predict part of the error left by a property-only model.
  \item \textbf{H3:} XGBoost predicts sale prices more accurately than a
  hedonic regression that uses the same features and the same test
  sales.
\end{itemize}

To test them, we built a data pipeline (Fig.~\ref{fig:pipeline}). We
start from the Auckland Council sales file, which has street addresses
but no map coordinates. We link each property to the official LINZ
address list with Splink~\cite{linacre2022}, a tool for probabilistic
record linkage, and keep 59,708 normal market sales of single homes.
The coordinate then lets us attach 16 external features from public
data. We train every model with time-ordered cross-validation, so it
always learns from earlier sales and is tested on later ones. A paired
bootstrap tests H1, a two-stage residual model tests H2, and a
comparison on the same folds tests H3. Finally, three importance
methods and SHAP show \emph{which} external data matters and
\emph{why} the model gives a certain price.

Our main contributions are:
\begin{enumerate}
  \item \textbf{A reproducible linked dataset.} We describe each step
  from the raw sales file to the model-ready data: record linkage,
  cleaning, and linking 16 external features from nine public sources.
  \item \textbf{A fair test of external data.} We keep the model and its
  settings fixed and change only the features. External data cuts RMSE
  by 38.1\% and MAPE from 19.3\% to 11.0\%, and explains 29.3\% of the
  error a property-only model leaves.
  \item \textbf{Evidence on what drives the gain.} Location carries most
  of it. Neighbourhood statistics carry real signal but largely repeat
  location, and hazard and building-activity features add almost
  nothing at city scale.
  \item \textbf{A comparison of five models with per-sale explanations.}
  XGBoost is the most accurate of five model types trained on the same
  inputs (MAPE 11.0\% vs 15.7\% for a hedonic regression). All five agree
  on the most important features, and SHAP gives each prediction a short
  explanation a buyer can read.
  \item \textbf{An honest benchmark against an online tool.} On 46 recent
  sales, homes.co.nz estimates recorded before each sale beat our model
  (MAPE 6.0\% vs 9.6\%), even when our model is retrained up to the same
  date. This shows where public data runs out and what the explanation
  costs in accuracy.
\end{enumerate}

The rest of the paper is organised as follows.
Section~\ref{sec:related} reviews related work.
Section~\ref{sec:method} describes the pipeline, the models and how we
test each hypothesis. Section~\ref{sec:results} presents and discusses
the results. Section~\ref{sec:limits} sets out the limitations, and
Section~\ref{sec:conclusion} concludes and suggests future work.

\section{Related Work}\label{sec:related}

\subsection{Hedonic models and outside factors in Auckland}
A hedonic model treats a house as a bundle of features, each with its own
price, found by regressing sale price on those
features~\cite{rosen1974}. These models are mainly used to
\emph{explain} the effect of each feature, not to predict new sales as
well as possible~\cite{shmueli2010}. Auckland studies show that factors
outside the property matter. Adding valuer-defined submarkets improved a
hedonic model more than switching to more complex spatial
models~\cite{bourassa2007}. Flood-prone homes on the North Shore sold for
about 6.2\% less before flood maps were published and 2.3\% less
afterwards~\cite{samarasinghe2010}. A popular school zone raised
prices~\cite{rehm2008}, leaky-building stigma lowered them by about
5\%~\cite{rehm2009}, and nearby social housing lowered them by
1.7--23\%~\cite{sequeira2021}. Overseas work shows that ignoring the link
between nearby sales can overstate an outside effect such as
flooding~\cite{bui2024}. Each of these studies looks at one factor in a
linear model, so none shows how much a \emph{combined} set of outside
data improves prediction. We add 16 external features to one model at
once and measure the change in error on unseen sales.

\subsection{Machine learning versus hedonic models}
Tree-based models learn curved effects and interactions from the data
without the analyst choosing their shape. They usually predict prices
better than hedonic regression: a random forest reached a MAPE of about
7\% against 17\% for regression on Ljubljana apartments~\cite{ceh2018},
and an $R^2$ of 0.94 against 0.65 on Busan condominiums~\cite{an2025}. In
Russia a random forest also won (MAPE 14.9\% vs 18.3\%), but its error
was much higher for large apartments~\cite{antipov2012}, so one overall
number can hide weak spots. Gradient-boosted trees such as
XGBoost~\cite{chen2016xgboost} do similarly well. Soltani
\textit{et al.}~\cite{soltani2022} stressed that features and training
data must only use sales that happened \emph{before} the sale being
predicted. Most comparisons change the model and the features at the
same time, so it is unclear how much of the gain comes from better data.
We change only one at a time: the features with the model fixed (H1),
then the model with the features fixed (H3), always training on past
sales only.

\subsection{External data and explainable models}
SHAP~\cite{lundberg2017} splits each prediction into one contribution
per feature, which makes machine learning models easier to read. In
Lisbon, open data on the surroundings cut MAE by 8.24\%, and SHAP ranked
longitude and latitude among the top features~\cite{neves2024}. In
Sydney, SHAP showed that the effect of amenities changed with distance
and amenity type~\cite{lee2025}, and in Beijing, location mattered most
and other effects varied by area~\cite{chen2025beijing}. These studies
rank features with SHAP alone. When features overlap, as coordinates and
area statistics do, one ranking can mislead. We therefore test first
whether external data helps, and then compare three importance methods
that react differently to overlap.

\subsection{Record linkage}
Public sales data often has addresses but no coordinates. The
Fellegi--Sunter model~\cite{fellegi1969} links records with no shared key
by weighing how strongly each field agrees. Splink~\cite{linacre2022}
implements this model at scale and estimates it without labelled pairs.
House price studies rarely report how their coordinates were obtained or
how many sales were lost. We describe this step in full, because every
external feature depends on it.

\subsection{Auckland sales data}\label{sec:sales}
Our main data is the Auckland Council sales file~\cite{akl_dvr}. It
lists 92,010 property sales from January 2024 to August 2026, with 41
columns that describe the sale (price, date, sale type) and the property
(land area, floor area, building age, condition, garages, and so on).
Each property has a council valuation reference and a street address: a
house number, an optional unit or letter, and a street name with a short
road type (for example ``St Michaels AV''). The file has no coordinates
and no suburb, so on its own it cannot tell us \emph{where} a home is.

\subsection{Linking sales to coordinates with Splink}\label{sec:linkage}
% ------------------------------------------------------------------
% The \ph{} items below are the Splink settings that are not recorded in
% this repository (only the output, dvrs_LINZ_matched.csv, is). Dominik:
% please fill them in from the linkage code. Every number outside a \ph{}
% was checked against dvrs_LINZ_matched.csv and the sales file.
% ------------------------------------------------------------------
To place each property on the map, we linked it to the LINZ NZ
Addresses list~\cite{linz_addresses}, which gives a coordinate for every
official address in New Zealand. The two sources share no key, and the
same address is often written differently (short forms, unit formats,
missing letters or typing errors). An exact join on the address text
would miss many homes and could not tell a near miss from a wrong
address.

We therefore used probabilistic record linkage with
Splink~\cite{linacre2022,splink_docs}, which implements the
Fellegi--Sunter model~\cite{fellegi1969}. For a candidate pair of records
(one sale address, one LINZ address), the model compares several fields.
Each comparison has a few ordered levels, such as exact agreement, close
agreement by a string-similarity score, disagreement, and missing. For
level $\ell$ of comparison $k$, the model learns two probabilities:
$m_{k\ell}$, the chance of seeing that level when the two records are
the same address, and $u_{k\ell}$, the chance of seeing it when they are
not. It adds up the evidence from all comparisons into a match weight
\begin{equation}
  w = \log_2\frac{\lambda}{1-\lambda}
      + \sum_{k}\log_2\frac{m_{k\gamma_k}}{u_{k\gamma_k}},
  \qquad
  p = \frac{2^{w}}{1+2^{w}},
  \label{eq:linkage}
\end{equation}
where $\gamma_k$ is the level seen for comparison $k$, $\lambda$ is the
prior chance that a random pair is a match, and $p$ is the match
probability. Agreement adds weight and disagreement removes it; the
rarer an agreement is among non-matching pairs, the more weight it adds.

The model needs no hand-labelled pairs. The $u$ values are estimated from
random pairs, which are almost all non-matches, and the $m$ values with
the expectation--maximisation (EM) algorithm~\cite{linacre2022}. Splink
can also adjust for term frequency, so that agreeing on a rare street
name counts more than agreeing on a common one. To keep the number of
pairs manageable, only pairs that pass a blocking rule are scored.
\ph{Blocking rules used, e.g.\ same street name, or same house number and
first letters of the street name.} \ph{Fields compared and their levels,
e.g.\ house number (exact), unit/letter (exact or missing), street name
(exact, Jaro--Winkler $\ge$ 0.9, else), road type; any cleaning applied
first, such as lower-casing and expanding road-type short forms; whether
term-frequency adjustment was used.}

Each valuation reference takes the LINZ address with the highest match
weight, as long as the weight is above \ph{threshold, as a match weight
or match probability}. \ph{Clerical review: how many pairs were checked
by hand, in which match-weight bands, and the false-match rate found.}
This links 81,363 of the 85,180 distinct properties in the sales file
(95.5\%) to one LINZ address and coordinate. A few LINZ addresses (72)
are shared by two valuation references, for example two cross-leased
homes at one street number. We join the coordinates back to the sales by
valuation reference, built from the roll number, the assessment number
and the lower-cased suffix that separates units under one assessment.

We kept only sales that show a normal market price for one home.

The zoning and unit filters remove commercial properties and buildings
with several homes. The tenure filter removes leasehold sales, which sell
for less because the buyer does not own the land. The one-property
filter matters most: when several properties are sold together, the
record shows one combined price but the features of only one property,
so the model cannot learn from it. The arm's-length filter removes sales
between related parties, which may not reflect market value. Linkage
found a coordinate for 97.6\% of the remaining sales. We then removed
records that repeat the same property, date and price, and three records
whose building floor area is more than ten times the council's
mass-appraisal floor area (for example 360,000~m\textsuperscript{2} for an
ordinary house), which are typing errors.

We also removed five columns that would leak the answer (data leakage).
The net, chattels and other price columns add up to the sale price. The
council's capital value and land value are themselves price estimates,
so a model that used them would copy the council's valuation instead of
learning from property and location data.

\subsection{Linking external features}\label{sec:external}
With a coordinate for every sale, we attached 16 external features from
nine public sources (Table~\ref{tab:sources}). All distances are
measured in metres in the New Zealand Transverse Mercator projection
(NZTM2000). We used three kinds of join:
\begin{itemize}
  \item \textbf{Nearest distance.} Straight-line distance to a fixed CBD
  point (Queen Street, 174.7645\textdegree E, 36.8485\textdegree S), to
  the nearest of 2,564 open schools, and to the nearest point on the
  coastline. To make the coastline search fast, we placed a point every
  20~m along the coast and found the nearest one with a k-d tree; this
  is within about 10~m of the exact distance. Walking distances to the
  nearest supermarket and bus stop follow the road network.
  \item \textbf{Point in polygon.} We found the 2025 Statistical Area 2
  (SA2) that contains each home, and whether the home lies in a council
  flood plain or an aircraft noise area.
  \item \textbf{Area lookup.} Through the SA2, each home gets its
  area's NZDep2023 deprivation decile (1 = least deprived, 10 = most),
  2023 Census statistics and the number of new dwellings consented in
  the past 12 months. Employment rate is employed people divided by
  people aged 15 and over; unemployment rate is unemployed people divided
  by the labour force; population density is the SA2 population divided
  by its land area.
\end{itemize}
Every sale found an SA2 and an NZDep2023 value. SA2 statistics are
area-level values shared by every home in the same SA2.

Land area, floor area and the two walking distances are right-skewed
(a few very large values), so we applied $\log(1+x)$ to them.

\textbf{Removing near-copies.} We dropped two features before modelling.
Sale quarter is calculated from sale month, and the council's
mass-appraisal floor area repeats the building floor area (Spearman
$\rho = 0.96$). Both pairs had a variance inflation factor (VIF) of
17--18, well above the usual limit of 10. Dropping them cost XGBoost
only \$212 of RMSE (0.1\%), and afterwards no feature has a VIF above
7.3. This matters more for explanation than for accuracy: two copies of
a feature share its SHAP credit and make both look less important than
they are.

\subsection{Training and testing over time}\label{sec:split}
House prices change over time, so a model should only learn from sales
that happened before the ones it predicts. Shuffling the data at random
would let the model learn from the future, which makes results look
better than they would be in practice~\cite{soltani2022}.

We therefore sort the 59,708 sales by date and use five-fold
expanding-window cross-validation (Fig.~\ref{fig:folds}). The data is cut
into six back-to-back time blocks of about 9,950 sales. In fold $k$, the
model trains on blocks $1$ to $k$ and is tested on block $k+1$, so each
fold learns from more history than the one before. Every sale after the
first block is tested exactly once, by a model that has never seen it.

Inside each fold, all preprocessing is learned from the training blocks
only and then applied to the test block: category codes (a category not
seen in training gets its own code), the median used to fill missing
walking distances (1.4--2.7\% of sales), and the price limits below.
Before training, we remove sales priced below the 1st or above the 99th
percentile of the training prices (\$430,000--\$450,000 and
\$4.2M--\$4.5M, depending on the fold), and apply the same limits to the
test block. This stops a few extreme sales from dominating the error,
but it means our results describe the middle 98\% of the market. After
this step, 48,777 test predictions remain across the five folds.

  \centering
  \figph{../figures/timeseries_split.png}{3cm}{Expanding-window folds.}
  \caption{Five-fold expanding-window cross-validation. Each fold trains
  on all earlier sales and tests on the next period.}
  \label{fig:folds}
\end{figure}

For $n$ test sales with actual price $y_i$ and predicted price
$\hat{y}_i$, we report three error measures:
\begin{align}
  \mathrm{MAE}  &= \frac{1}{n}\sum_{i=1}^{n}\lvert y_i-\hat{y}_i\rvert,
  \label{eq:mae}\\
  \mathrm{RMSE} &= \sqrt{\frac{1}{n}\sum_{i=1}^{n}(y_i-\hat{y}_i)^2},
  \label{eq:rmse}\\
  \mathrm{MAPE} &= \frac{100}{n}\sum_{i=1}^{n}
                   \frac{\lvert y_i-\hat{y}_i\rvert}{y_i}.
  \label{eq:mape}
\end{align}
MAE is the typical error in dollars. RMSE gives more weight to large
errors, which matter most for expensive homes. MAPE is the error as a
percentage of price, so a \$100K miss on a \$600K home counts more than
the same miss on a \$3M home. We pool the test predictions from all five
folds and compute each measure once.

\subsection{Models}\label{sec:models}
Our main model is XGBoost~\cite{chen2016xgboost}, a gradient-boosted
tree model that predicts the sale price in dollars. We chose it because
it handles curved effects and mixed feature types well, and tree models
beat linear regression in earlier house price
studies~\cite{ceh2018,an2025}. It uses 500 trees, maximum depth 6,
learning rate 0.05, 80\% of rows and of features sampled per tree, and
random seed 42. To check that our results do not depend on one
algorithm, we train four more models on exactly the same inputs:
\begin{itemize}
  \item \textbf{Random forest}~\cite{breiman2001}: 150 trees, maximum
  depth 18, at least 2 sales per leaf.
  \item \textbf{CatBoost}~\cite{prokhorenkova2018}: 500 trees, depth 6,
  learning rate 0.05, set to match XGBoost. It gets the same integer
  category codes as the other models.
  \item \textbf{Neural network}: a multilayer perceptron with a learned
  embedding for each categorical feature and three hidden layers (256,
  128 and 64 units, ReLU, dropout 0.1), trained with
  Adam~\cite{kingma2015} (learning rate $10^{-3}$, batch 512) on the
  standardised log price. Training stops when the error on the latest
  10\% of the training period has not improved for 10 epochs. Inputs are
  clipped to the training 0.5th--99.5th percentiles.
  \item \textbf{Hedonic regression}, described next.
\end{itemize}
We do not tune any model. If each model were tuned separately, part of
any difference could come from tuning rather than from the features or
the algorithm. Fixed settings keep the comparisons fair, at the cost of
slightly understating what each model could reach.

\textbf{Hedonic regression.}\label{sec:hedonic} The traditional approach
is a linear regression on the log of price,
\begin{equation}
  \ln y_i = \beta_0 + \mathbf{x}_i^{\top}\boldsymbol{\beta}
            + \varepsilon_i,
  \label{eq:hedonic}
\end{equation}
fitted by ordinary least squares on the same 27 features. Each category
is one-hot encoded, with its most common level as the reference, and any
column that never changes in a fold's training data is dropped for that
fold. As for the neural network, numeric inputs are clipped to the
training 0.5th--99.5th percentiles, so one unusual value cannot produce
an extreme price. Turning a log prediction back into dollars with
$\exp(\cdot)$ underestimates the average price, so we multiply by
Duan's smearing factor~\cite{duan1983}:
\begin{equation}
  \hat{y}_i = \exp\!\left(\hat{\beta}_0 + \mathbf{x}_i^{\top}
  \hat{\boldsymbol{\beta}}\right)\cdot
  \frac{1}{m}\sum_{j=1}^{m}e^{\hat{\varepsilon}_j},
  \label{eq:smearing}
\end{equation}
where $\hat{\varepsilon}_j$ are the $m$ training residuals. The neural
network uses the same correction.

\subsection{Testing the hypotheses}\label{sec:tests}
\textbf{H1: paired bootstrap.} We train XGBoost on the baseline and the
augmented feature set over the same folds. To check that the augmented
model is better and not just lucky, we draw $n$ test sales at random with
replacement and compute
\begin{equation}
  \Delta^{(b)} = M_{\text{base}}^{(b)} - M_{\text{aug}}^{(b)}
  \label{eq:bootstrap}
\end{equation}
for each metric $M$~\cite{efron1993}. Both models are scored on the same
resampled sales, so the test is paired. We repeat this $B=2{,}000$
times; the 2.5th and 97.5th percentiles of $\Delta^{(b)}$ give a 95\%
confidence interval. If it does not include zero, the improvement is
statistically significant.

\textbf{H2: two-stage residual test.} H1 shows that external features
help, but the model might only use them to relearn something the
property features already contain. In stage~1, we take the baseline
model's out-of-fold errors $r_i = y_i - \hat{y}_i^{\text{base}}$. In
stage~2, a new XGBoost model sees \emph{only} the 16 external features
and predicts $r_i$, with its own five-fold expanding-window split over
these sales in date order. The first block (8,132 sales) is training
only, leaving 40,645 sales with a stage-2 prediction. Stage~2 never sees
a property feature, so an out-of-fold $R^2$ above zero means the
external features explain something the property features missed.

\textbf{H3: same-fold comparison.} All five models of
Section~\ref{sec:models} use the same features, folds, price limits and
metrics, so any difference comes from the model alone. We compare their
pooled errors and their errors in each fold.

\subsection{Which external features matter}\label{sec:attribution}
To see which external data drives the gain, we use fold~5: the model
trains on all sales up to January 2026 and is tested on the 9,769 sales
from January to August 2026. We study the four external groups of
Table~\ref{tab:features} with three methods:
\begin{itemize}
  \item \textbf{Grouped permutation importance:} shuffle all features of
  a group together in the test set and measure the RMSE increase
  (average of 20 repeats).
  \item \textbf{SHAP:} the share of a group in the total mean absolute
  SHAP value, on 500 test sales.
  \item \textbf{Drop-group retraining:} retrain without the group (or
  without one feature) and measure the change in RMSE.
\end{itemize}
The three react differently when two groups carry similar information.
Permutation breaks a group while the model still relies on it, so it
shows how much the model \emph{uses} the group, which can overstate how
much it is \emph{needed}. Drop-group retraining lets the model fall back
on a similar group, so it shows what is \emph{unique} to the group but
can understate its value. SHAP splits the credit between similar
features. Reading them together shows both use and uniqueness.

\subsection{Explaining single predictions}\label{sec:explain}
SHAP values add up: for each sale, the model's average prediction plus
the SHAP value of every feature equals the prediction. We use this to
explain one held-out sale at a time. Starting from the average predicted
price, each feature adds or removes a dollar amount. For a short
summary, we add up the contributions within five themes (the four
external groups plus ``house and land''), which is valid because SHAP
values are additive. A waterfall chart shows the largest single
contributions with feature values in real units (square metres,
kilometres, deciles). For the tree models we use exact
TreeSHAP~\cite{lundberg2017}; for the neural network and hedonic model
we use SHAP's permutation explainer with 100 training sales as
background.

\subsection{Online valuation benchmark}\label{sec:onlineval}
To test the second half of RQ2, we compared our model with
HomesEstimate, the free automated estimate on homes.co.nz~\cite{homesnz}.
Online estimates are updated after a sale, so an estimate looked up
later may already reflect the sale price and make the online tool look
better than it was. We avoid this by using estimates recorded on
\textbf{9 July 2026}, before every sale in the sample.

We took the 50 most recent sales in our dataset (28 July to 18 August
2026), so each sold 19--40 days after its estimate was recorded. Two
were outside the model's price limits (Section~\ref{sec:split}) and two
had no estimate, leaving \textbf{46 homes}. We compare two versions of
our XGBoost model on these homes:
\begin{itemize}
  \item \textbf{Ours (to 24 Jan):} the fold-5 prediction used in the rest
  of the paper, from a model trained on sales up to 24 January 2026.
  \item \textbf{Ours (to 9 Jul):} the same model retrained on all 58,223
  sales before 9 July 2026, so that it knows the market up to the same
  day as the online estimates.
\end{itemize}
Besides MAE, RMSE and MAPE, we report the share of homes predicted within
5\% and 10\% of the sale price, a common way to judge automated
valuations. With only 46 homes, we test the MAPE gap in two paired ways:
a paired bootstrap (Eq.~\ref{eq:bootstrap}, 2,000 resamples) and a
Wilcoxon signed-rank test~\cite{wilcoxon1945} on the per-home absolute
percentage errors, which does not assume the errors are normally
distributed.

\section{Experiments and Results}\label{sec:results}

\subsection{H1: Does external data help?}\label{sec:res-ablation}
Table~\ref{tab:ablation} and Fig.~\ref{fig:ablation} give the pooled
error over all five folds. Adding the 16 external features cuts RMSE by
\$131,040, from \$343,718 to \$212,678 (38.1\%), MAE by \$95,242, and
MAPE by 8.4 percentage points, from 19.3\% to 11.0\%. The paired
bootstrap gives 95\% confidence intervals of \$126,988--\$135,157 for the
RMSE gain, \$93,358--\$97,194 for MAE and 8.2--8.5 points for MAPE. None
includes zero, so \textbf{H1 is supported}. The gain is also steady over
time: the augmented model wins in every fold, with RMSE between
\$191,483 and \$238,373 against \$320,862 to \$370,069 for the baseline.
Both models also improve in later folds, which have more training
history.

What does this mean in practice? A typical error of \$128,000 is still a
lot of money, but it is about half of the \$223,000 typical error of a
model that only knows the house. Two homes with the same size, age and
condition can differ in price by hundreds of thousands of dollars
depending on where they are, and the baseline model has no way to see
this.

\subsection{H2: Do external features add new information?}
A model could look like it needs external data only because the property
features are weak. The two-stage test rules this out. A model that sees
\emph{only} the 16 external features explains 29.3\% of the variance in
what the property-only model gets wrong ($R^2=0.293$ on 40,645 held-out
errors), and cuts the RMSE of those errors from \$339,582 to \$285,308.
Since this model never sees a property feature, the 29.3\% must be
information the property features do not contain, so \textbf{H2 is
supported}. The other 70.7\% is not explained by our external data. It
likely comes from things neither data source records, such as interior
quality, views, renovations and the negotiation itself.

\subsection{Which external features matter?}\label{sec:res-attribution}
Table~\ref{tab:attribution} compares the three methods on fold~5 (9,769
test sales, augmented RMSE \$191,483). Together, the external features
hold 52.3\% of the model's total SHAP value, and dropping all of them
raises RMSE by \$129,379, in line with the five-fold result above.

\textbf{Location matters most} on all three measures. Distance to the
CBD alone holds 15.5\% of total SHAP, more than latitude (8.1\%) or
longitude (8.6\%), and is second only to building floor area (21.0\%)
across all 27 features (Fig.~\ref{fig:shap}). The SHAP plot shows the
shape of this effect: being close to the CBD raises the price a lot,
while beyond a certain distance further kilometres change little. A
straight-line model cannot capture this shape.

\textbf{Neighbourhood statistics mostly repeat location.} The model
clearly uses them: shuffling the group raises RMSE by 32.1\%, and it
holds 16.1\% of SHAP, led by the deprivation decile (6.9\%). Yet
retraining without the group costs only \$1,665, because the model
recovers almost the same information from location. The reverse is not
true: without the location group the model still loses \$20,146, even
though the neighbourhood statistics remain. Without all external
features it loses \$129,379, more than six times the sum of the four
single-group losses. In plain terms, location and neighbourhood
statistics describe much the same thing (how desirable an area is), and
location describes it more fully. The same holds for single features: no
external feature costs more than \$3,752 when dropped alone (latitude),
and for eight of them the model is slightly better without them, within
noise. This is why one ranking method on its own would mislead.

\textbf{Hazards and building activity add almost nothing at city
scale.} Only 6.4\% of sales lie in a flood plain and 5.3\% in an aircraft
noise area. These features may matter for those homes, but they cannot
explain much of the price variation across all of Auckland. The
12-month count of consents in an SA2 changes slowly and overlaps with
location.

\subsection{RQ2: Accuracy versus interpretability}\label{sec:res-hedonic}
The hedonic model's strength is that each coefficient has a one-sentence
meaning that holds for every house. On fold~5, for example, each extra
\$10,000 of median personal income in the SA2 goes with 12.3\% higher
prices, each kilometre further from the CBD with 1.2\% lower prices, each
step up the deprivation decile with 1.3\% lower prices, and a flood
plain location with 1.8\% lower prices, all else equal. XGBoost cannot
give one number per feature, because a feature's effect changes from
sale to sale. Instead, SHAP gives a dollar breakdown for each
prediction (Section~\ref{sec:res-explain}). This is the trade-off RQ2
asks about: the machine learning model gives up one global number per
feature, but keeps a clear per-sale explanation while cutting the
hedonic model's MAPE by about 30\%.

\subsection{Explaining a single prediction}\label{sec:res-explain}
Fig.~\ref{fig:house} explains one held-out sale from fold~5's test
period: a home sold in June 2026 for \$1,285,000. The XGBoost model,
trained only on sales up to January 2026, predicted \$1,266,131 (1.5\%
below). Starting from the average prediction of \$1,151,033:
\begin{itemize}
  \item the \emph{neighbourhood} adds \$65,399, mostly from a low
  deprivation decile (2 of 10, +\$71,055);
  \item \emph{location} adds \$41,119: the home's latitude (+\$85,033)
  outweighs its 16.9~km distance from the CBD ($-$\$63,763);
  \item the \emph{house and land} add \$26,184: a large floor area
  (172~m\textsuperscript{2}, +\$84,080) more than offsets a small section
  (186~m\textsuperscript{2}, $-$\$94,139);
  \item \emph{market timing} (a 2026 sale) removes \$19,070, and
  \emph{hazards} change the price by only \$1,469.
\end{itemize}
This is the kind of reason an online valuation tool does not give: a
buyer can see that the price rests on the area and the size of the
house, not on the section.

\subsection{RQ2: Comparison with online valuation estimates}
\label{sec:res-online}
Table~\ref{tab:online} compares our model with
homes.co.nz on the same 46 homes. \textbf{homes.co.nz is clearly more
accurate.} Its MAPE is 6.0\% against 9.6\% for our model, and half of its

gap is not luck: the paired bootstrap gives a 95\% confidence interval
of 1.3--6.0 points for the MAPE gap, and the Wilcoxon test gives
$p = 0.012$. Our model is closer to the sale price on 17 of the 46 homes
(37\%), and Fig.~\ref{fig:online-homes} shows that when it loses, it
often loses by a wide margin. On these homes our own error (9.6\%) is close to its error on all
test sales (11.0\%), so the result reflects the online tool's strength,
not an unlucky sample for our model.

\textbf{The gap is not about timing.} Our fold-5 model only knows sales
up to January, about 5.5 months before the online estimates were
recorded. Yet retraining it on all sales up to 9 July does not help
(MAPE 9.9\%; bootstrap interval 1.6--6.3 points, $p = 0.007$). The
difference must therefore come from \emph{information}, not from how
recent the training data is.

\textbf{Where does the extra information come from?} Our largest misses
are homes whose value depends on things the council file does not
record: our model predicts 34\% too high for one home and 25\% too low
for a \$4.1M home near the top of our price range, where we have few
sales to learn from (right end of Fig.~\ref{fig:online-homes}).
Where our model is closer (left end), its wins are usually smaller. An online tool can draw on richer property data,
and by 9 July many of these homes were probably already listed for sale,
with photos and descriptions that such a tool may use. A few online
estimates land within 1\% of the final price, which fits this picture.
Our model, by design, uses only public council and area data and never
sees a listing.

This answers the second half of RQ2. Our model is far more accurate than
the traditional hedonic approach and explains every prediction in
dollars, but it does not reach the accuracy of a commercial estimate
built on richer data, and homes.co.nz gives no reason for its number.
The 3.6-point MAPE gap is the current cost of building only on
open data, and it shows what to add next: better data about the house
itself.

%% ============= V. LIMITATIONS, VI. CONCLUSION ========================
\section{Limitations}\label{sec:limits}
\textbf{Coverage.} Our price filter keeps the middle 98\% of each fold's
training prices, so the results describe the typical Auckland home and
may not hold for the cheapest or most expensive 1\%. Record linkage
placed 97.6\% of the arm's-length single-home sales; if the missing
2.4\% are different (for example new subdivisions not yet in LINZ), our
results could be slightly off for that part of the market. The data also
covers one city over 2024--2026, a fairly flat market, so the size of
the gain may differ elsewhere or in a fast-rising market.

\textbf{Area data.} The neighbourhood features are 2023 Census and
NZDep2023 values for the whole SA2. Every home in an SA2 shares them,
they do not change over 2024--2026, and they describe the area, not the
buyer. We had school locations but not enrolment zones, so we could not
test school-zone effects.

\textbf{Explanations are not causes.} SHAP and the other methods show
how the model uses a feature, not what causes prices to change: a large
SHAP value for the deprivation decile does not mean deprivation
\emph{causes} a set dollar change in price. Because location and
neighbourhood features overlap, the split of credit between them depends
on the method, so no single number should be read as the ``true'' value
of one feature.

\textbf{Fixed settings.} We fixed every model's settings for a fair
comparison. A project that only cared about accuracy could tune each
model and would likely do somewhat better than every number here.

\textbf{Small online benchmark.} The online comparison uses 46 homes
from three weeks of sales, mostly in the middle of the market, and one
online tool. The direction of the result is clear, but the exact size of
the gap is uncertain, and other tools (such as propertyvalue.co.nz or
OneRoof) may score differently.

\section{Conclusion and Future Work}\label{sec:conclusion}
This paper asked whether Auckland-specific external data improves house
price prediction (RQ1), and how an explainable model built on it compares
with a traditional hedonic model and free online valuations (RQ2). We
built a pipeline from the Auckland Council sales file to a linked
dataset: Splink record linkage gave each property a LINZ coordinate, and
the coordinate let us attach 16 external features from nine public
sources. We then tested the models with time-ordered cross-validation,
so every prediction was made from past sales only.

For RQ1, the answer is yes, by a wide and significant margin. Adding the
external features cuts XGBoost's RMSE by 38.1\% and MAPE from 19.3\% to
11.0\% (H1), and a model that sees only external data explains 29.3\% of
the error a property-only model leaves (H2). The reason is simple: two
similar houses in different places can sell for very different prices,
and only the external features tell the model where a house is and what
its area is like. For the first part of RQ2, XGBoost is the most
accurate of five models and far more accurate than a hedonic regression
on the same features (MAPE 11.0\% vs 15.7\%, H3), because it can learn
curved and local effects. It still explains each prediction in dollars
through SHAP. For the second part of RQ2, a free online estimate
(homes.co.nz) recorded before each sale was more accurate on 46 recent
sales (MAPE 6.0\% vs 9.6\%), even after we retrained our model up to the
same date. Public council and area data take us most of the way, but
not all the way, to a commercial estimate; the rest seems to need
richer data about the house itself.

The clearest practical finding is that most of the value of external
data is the value of \emph{location}. Distance to the CBD and the
coordinates carry the largest share; area census and deprivation
statistics are useful but mostly repeat what location already says; and
flood, noise and building-activity features add almost nothing to a
city-wide model. For a team building a similar model with limited time,
an accurate coordinate (here, good record linkage) and a few location
measures are worth more than many extra area features.

The main drawbacks are that the model is less accurate for unusual
homes, that area data is coarse and fixed in time, and that SHAP shows
association, not cause. If this work continued as a master's project, we
would: (1) repeat the online benchmark on a larger sample and several
tools, recording estimates for homes as they are listed, and test
whether listing data (photos, descriptions) closes the gap; (2) tune
each model
and add a prediction interval (for example with quantile regression or
conformal prediction), so a buyer sees a range, not just one number;
(3) test whether hazards matter more in the parts of Auckland where they
are common, using location--feature interaction methods such as
GeoShapley~\cite{li2024geoshapley}; (4) add school enrolment zones and
recent nearby sales, built only from earlier sales~\cite{soltani2022};
and (5) improve the record linkage to recover the 2.4\% of sales without
a coordinate and check whether they change our conclusions.
