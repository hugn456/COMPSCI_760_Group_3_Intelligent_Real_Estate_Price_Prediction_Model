%% =========================== ABSTRACT ================================
\begin{abstract}
House prices shape lending, rates and most families' biggest financial
decision, yet free online valuation tools give a price without a
reason. We build an explainable machine-learning pipeline for Auckland
house prices and ask whether data about a home's surroundings improves
prediction. From 92,010 Auckland Council sales (2024--2026), we use
Splink-based record linkage to give properties a LINZ coordinate, keep
59,708 market sales, and link 16 external features:
location, 2023 Census and deprivation statistics, flood and noise
exposure, and building activity. Under time-ordered five-fold
cross-validation, adding these features to the same XGBoost model cuts
RMSE from \$343,718 to \$212,678 and MAPE from 19.3\% to 11.0\%. A
paired bootstrap shows the gain is significant, and a two-stage test
shows the external features explain 29.3\% of the variance in a
property-only model's errors. Three importance methods agree that
location drives most of the gain. XGBoost beats four other models,
including a hedonic regression (MAPE 11.0\% vs 15.7\%), and SHAP
explains each prediction in dollars. On 45 recent sales, two free online
estimates (homes.co.nz and OneRoof) recorded before each sale were more
accurate (MAPE 5.8\% vs 9.6\%), pointing to the value of richer property
data.
\end{abstract}

\begin{IEEEkeywords}
house price prediction, explainable AI, SHAP, record linkage, Splink,
gradient boosting, hedonic regression, Auckland
\end{IEEEkeywords}

%% ========================= I. INTRODUCTION ===========================
\section{Introduction}\label{sec:intro}

For most New Zealand households, a home is the largest thing they will
ever buy. Its value matters to many people: buyers and sellers use it to
set a price, banks use it to decide how much to lend, and Auckland
Council uses it to set rates. In Auckland, these values are hard to
predict. Homes differ a lot in size, age and condition, and so do the
places they sit in. Some areas are close to the city centre or the coast,
some neighbourhoods are much richer than others, and some homes sit in a
flood plain or under a flight path. A model that only looks at the house
itself is therefore likely to miss a large part of its price.

Free online valuation tools give buyers a number but not a reason. A
buyer cannot see whether an estimate is high because of the house, its
location or something else. This matters when the estimate informs a
decision worth around a million dollars.

Past research has studied this problem from two sides. Hedonic studies
of Auckland have measured the effect of one external factor at a time,
such as flood risk~\cite{samarasinghe2010}, school
zones~\cite{rehm2008}, leaky-building stigma~\cite{rehm2009} and social
housing~\cite{sequeira2021}. These models are easy to interpret, but they are
built to explain one effect, not to predict new
sales~\cite{shmueli2010}. Machine learning models predict prices more
accurately~\cite{ceh2018,an2025}, and SHAP~\cite{lundberg2017} can show
which features drive each prediction. However, we found no study that
applies explainable machine learning to Auckland, and few that measure
how much a \emph{combined} set of external data improves prediction on
sales the model has not seen.

This paper answers two research questions:
\begin{itemize}
  \item \textbf{RQ1:} Does adding Auckland-specific external features
  (location, neighbourhood, hazards and building activity) improve house
  price prediction compared with using only a property's own features?
  \item \textbf{RQ2:} How accurate and interpretable is our explainable
  model compared with a traditional hedonic model and free online
  valuation estimates for the same Auckland properties?
\end{itemize}
We test three hypotheses:
\begin{itemize}
  \item \textbf{H1:} The same XGBoost model predicts sale prices with
  lower error when the external features are added, and the drop in
  error is statistically significant.
  \item \textbf{H2:} The external features contain information that the
  property features do not, so a model that sees \emph{only} external
  features can predict part of the error left by a property-only model.
  \item \textbf{H3:} Machine learning models (XGBoost, CatBoost, random
  forest and a neural network) predict sale prices more accurately than a
  hedonic regression that uses the same features and the same test
  sales.
\end{itemize}

Before choosing our main dataset, we tested collecting property data
from several public websites. However, we found that the records were
often incomplete or inconsistent, making them less suitable for our
experiments.

To test these hypotheses, we built a data pipeline
(Fig.~\ref{fig:pipeline}). We
start from the Auckland Council sales file, which has street addresses
but no map coordinates. We link the properties to the official LINZ
address list with uk\_address\_matcher~\cite{uam_docs}, a probabilistic
record linkage tool built on Splink~\cite{linacre2022}, and keep 59,708
normal market sales of single homes.
The coordinate then lets us attach 16 external features from public
data. We train every model with time-ordered cross-validation, so it
always learns from earlier sales and is tested on later ones. A paired
bootstrap tests H1, a two-stage residual model tests H2, and a
comparison on the same folds tests H3. This comparison also picks the
main model for the rest of the paper and checks that the SHAP findings
hold across different models. Finally, three importance methods show
\emph{which} external data matters, and SHAP explains \emph{why} the
model gives a certain price for a single home.

Our main contributions are:
\begin{enumerate}
  \item We build a reproducible linked dataset and describe each step
  from the raw sales file to the model-ready data: record linkage,
  cleaning, and linking 16 external features from nine public sources.
  \item We test the value of external data fairly, by keeping the model
  and its settings fixed and changing only the features. External data
  cuts RMSE by 38.1\% and MAPE from 19.3\% to 11.0\%, and explains
  29.3\% of the variance in the errors a property-only model leaves.
  \item We show that location drives most of this gain. Neighbourhood
  statistics carry real signal but largely repeat location, and hazard
  and building-activity features add almost nothing at city scale.
  \item We compare five models trained on the same inputs and explain
  their predictions sale by sale. XGBoost is the most accurate (MAPE
  11.0\% vs 15.7\% for a hedonic regression), all five agree on the most
  important features, and SHAP gives each prediction a short explanation
  a buyer can read.
  \item We benchmark our model honestly against two online tools. On 45
  recent sales, homes.co.nz and OneRoof estimates recorded before each
  sale beat our model (MAPE 5.8\% for both vs 9.6\%), even when our model
  is retrained up to the same date, which shows the limits of public
  data.
\end{enumerate}

The rest of the paper is organised as follows.
Section~\ref{sec:related} reviews related work.
Section~\ref{sec:method} describes the pipeline, the models and how we
test each hypothesis. Section~\ref{sec:results} presents and discusses
the results. Section~\ref{sec:limits} sets out the limitations, and
Section~\ref{sec:conclusion} concludes and suggests future work.

\section{Related Work}\label{sec:related}

\subsection{Hedonic models and outside factors in Auckland}
Rosen~\cite{rosen1974} described a house as a bundle of features, each
with its own price, found by regressing sale price on those features.
As Shmueli~\cite{shmueli2010} notes, such models are mainly used to
\emph{explain} the effect of each feature, not to predict new sales as
well as possible. Auckland studies show that factors outside the
property matter. Bourassa \textit{et al.}~\cite{bourassa2007} found that
adding valuer-defined submarkets improved a hedonic model more than
switching to more complex spatial models. Samarasinghe and
Sharp~\cite{samarasinghe2010} found that flood-prone homes on the North
Shore sold at a discount, which became smaller once flood-risk
information was made public. Rehm and Filippova~\cite{rehm2008} showed
that being zoned for popular state schools raised prices, though not
evenly; Rehm~\cite{rehm2009} found that leaky-building stigma lowered
them by about 5\%; and Sequeira and Filippova~\cite{sequeira2021} found
that nearby social housing lowered them by 1.7--23\%. Overseas, Bui
\textit{et al.}~\cite{bui2024} combined a hedonic model with spatial
econometrics and found that flood-affected homes in Ho Chi Minh City
sold for 9\% less after a major flood. Each of these studies looks at one factor in a
linear model, so none shows how much a \emph{combined} set of outside
data improves prediction. We add 16 external features to one model at
once and measure the change in error on unseen sales.

\subsection{Machine learning versus hedonic models}
Tree-based models learn curved effects and interactions from the data
without the analyst choosing their shape. They usually predict prices
better than hedonic regression. On Ljubljana apartments, \v{C}eh
\textit{et al.}~\cite{ceh2018} found that a random forest reached a MAPE
of about 7\% against 17\% for regression, and in Busan, An
\textit{et al.}~\cite{an2025} found that a random forest explained with
SHAP appraised condominium prices more accurately than hedonic models.
In Russia, Antipov and Pokryshevskaya~\cite{antipov2012} also found that
a random forest won (MAPE 14.9\% vs 18.3\%), but a closer check found
groups of apartments whose prices it consistently over- or
underestimated, so one overall number can hide weak spots.
Gradient-boosted trees such as XGBoost, by Chen and
Guestrin~\cite{chen2016xgboost}, do similarly well. Soltani
\textit{et al.}~\cite{soltani2022} stressed that features and training
data must only use sales that happened \emph{before} the sale being
predicted. Most comparisons change the model and the features at the
same time, so it is unclear how much of the gain comes from better data.
We change only one at a time: the features with the model fixed (H1),
then the model with the features fixed (H3), always training on past
sales only.

\subsection{External data and explainable models}
SHAP, by Lundberg and Lee~\cite{lundberg2017}, splits each prediction
into one contribution per feature, which makes machine learning models
easier to read. In Lisbon, Trindade Neves \textit{et
al.}~\cite{neves2024} found that open data on the surroundings cut MAE
by 8.24\%, and SHAP ranked longitude and latitude among the top
features. In Sydney, Lee \textit{et al.}~\cite{lee2025} used SHAP to show
that the effect of amenities on price changes with distance and differs
by amenity type, and in Beijing, Chen \textit{et
al.}~\cite{chen2025beijing} used GeoShapley to show that price effects
are non-linear and vary across the city. These studies
rank features with SHAP alone. When features overlap, as coordinates and
area statistics do, one ranking can mislead. We therefore test first
whether external data helps, and then compare three importance methods
that react differently to overlap.

\section{Methodology}\label{sec:method}

\subsection{Data source selection}\label{sec:datasource}
At the start of the project, we explored several sources of property
data, including Barfoot \& Thompson, OneRoof, realestate.co.nz and
homes.co.nz. We wrote Python web-scraping scripts to collect property
information from these websites and tested whether records from
different sources could be combined into a single dataset. We also
compared the types of information available, particularly property
characteristics, sale prices and historical sales records.

Although web scraping allowed us to collect property information, we
found several problems with the data. Some websites did not provide all
the property features we needed, and information about the same property
was sometimes inconsistent across sources. We also encountered
duplicated information and limited historical sales records, as many
websites mainly showed recent listings. In addition, much of the
information appeared to come from Auckland Council records. This meant
that combining data from these websites would require considerable
cleaning without necessarily producing a more complete or reliable
dataset.

We therefore decided to use Auckland Council's property and sales
records as our main data source (Fig.~\ref{fig:datasource}). Before
proceeding, we reviewed the data dictionary to understand the available
variables, checked the property and transaction information, and
examined the historical coverage to decide which records would be
suitable for our experiments. Compared with the websites we tested, the
Council data provided more structured property information and a longer
sales history. It also gave us a better starting point for linking
external data and training models on consistent property records. We
kept the preliminary web-scraped data as a backup, rather than using it
as our main modelling dataset.

We kept the data collected from our initial web-scraping experiments in
a shared Google Drive folder for reference. These records were not used
to train or evaluate our final models.

\subsection{Auckland sales data}\label{sec:sales}
Our main data is the Auckland Council sales file~\cite{akl_dvr}. It
lists 92,010 property sales from January 2024 to August 2026, with 41
columns that describe the sale (price, date, sale type) and the property
(land area, floor area, building age, condition, garages, and so on).
Each property has a council valuation reference and a street address: a
house number, an optional unit or letter, and a street name with a short
road type (for example ``St Michaels AV''). The file has no coordinates
and no suburb, so on its own it cannot tell us \emph{where} a home is.

\subsection{Linking sales to coordinates with Splink}\label{sec:linkage}
% Linkage settings from Dominik's write-up (splink report.docx); the
% 81,363 / 85,180 / 72 figures were checked against dvrs_LINZ_matched.csv.
To place each property on the map, we linked it to the LINZ NZ
Addresses list~\cite{linz_addresses}, which gives a coordinate for every
official address in New Zealand. The two sources share no key, and the
same address is often written differently (short forms, unit formats,
missing letters or typing errors). An exact join on the address text
would miss many homes and could not tell a near miss from a wrong
address.

We therefore used probabilistic record linkage with
uk\_address\_matcher~\cite{uam_docs}, an address-matching
package built on Splink~\cite{linacre2022,splink_docs}, which implements
the Fellegi--Sunter model~\cite{fellegi1969}. For a candidate pair of records
(one sale address, one LINZ address), the model compares several fields.
Each comparison has a few ordered levels, such as exact agreement, close
agreement by a string-similarity score, disagreement, and missing. For
level $\ell$ of comparison $k$, the model learns two probabilities:
$m_{k\ell}$, the chance of seeing that level when the two records are
the same address, and $u_{k\ell}$, the chance of seeing it when they are
not. It adds up the evidence from all comparisons into a match weight
\begin{equation}
  w = \log_2\frac{\lambda}{1-\lambda}
      + \sum_{k}\log_2\frac{m_{k\gamma_k}}{u_{k\gamma_k}},
  \qquad
  p = \frac{2^{w}}{1+2^{w}},
  \label{eq:linkage}
\end{equation}
where $\gamma_k$ is the level seen for comparison $k$, $\lambda$ is the
prior chance that a random pair is a match, and $p$ is the match
probability. Agreement adds weight and disagreement removes it; the
rarer an agreement is among non-matching pairs, the more weight it adds.

Before matching, we turned the separate address parts in both sources
into one standardised address string. We made the letter case
consistent, put the parts in the same order and made common
abbreviations the same in both sources. From this string, the package
derives the features it compares, such as the numbers in the address,
the road name and, where available, the postcode. Working from the whole
string, rather than only from fixed fields such as house number and
street name, copes better with addresses that are incomplete,
abbreviated or written in a different order.

Matching ran in two stages with the package's default settings. First,
records whose standardised strings were identical were matched directly.
Second, the remaining records were matched probabilistically: a blocking
step kept only plausible candidate pairs that share address features,
and a pretrained address-matching model scored each pair. Because the
$m$ and $u$ values come with this pretrained model, we needed no
hand-labelled pairs. The model also adjusts for term frequency, so that
agreeing on a common word counts less than agreeing on a rare,
distinctive one.

To choose a match-weight threshold, we reviewed matched pairs by hand.
We split the matches into match-weight bands five units wide and drew a
random sample of up to 50 pairs from each band. Starting with the
lowest band, we checked each sampled pair by comparing the two address
strings and, where needed, the location on an online map. A band was
accepted when fewer than 2\% of its sampled pairs were false matches.
The first band to pass was $[0, 5)$, and since higher weights mean
stronger evidence of a match, we kept every match with a weight of at
least 0, taking the best-scoring LINZ address for each valuation
reference. This links 81,363 of the 85,180 distinct properties in the sales file
(95.5\%) to one LINZ address and coordinate; a few LINZ addresses (72)
are shared by two valuation references. We join the coordinates back to the sales by
valuation reference, built from the roll number, the assessment number
and the lower-cased suffix that separates units under one assessment.

We kept only sales that show a normal market price for one home.

The zoning and unit filters remove commercial properties and buildings
with several homes. The tenure filter removes leasehold sales, which sell
for less because the buyer does not own the land. The one-property
filter is important here because when several properties are sold
together, the record shows one combined price but the features of only
one property, so the model cannot learn from it. The arm's-length filter
removes sales between related parties, which may not reflect market
value. Linkage found a coordinate for 97.6\% of the remaining sales. We
then removed records that repeat the same property, date and price,
which are duplicates, and three records whose building floor area is
more than ten times the council's mass-appraisal floor area (for example
360,000~m\textsuperscript{2} for an ordinary house).

We also removed five columns that would leak the answer (data leakage).
The net, chattels and other price columns add up to the sale price. The
council's capital value and land value are themselves price estimates,
so a model that used them would copy the council's valuation instead of
learning from property and location data.

\subsection{External features and feature sets}\label{sec:external}
With a coordinate for every sale, we attached 16 external features from
nine public sources (Table~\ref{tab:sources}). All distances are
measured in metres in the New Zealand Transverse Mercator projection
(NZTM2000). We used three kinds of join.

The first measures distances. We computed the straight-line distance to
a fixed CBD point (Queen Street, 174.7645\textdegree E,
36.8485\textdegree S), to the nearest of 2,564 open schools, and to the
nearest point on the coastline. To make the coastline search fast, we
placed a point every 20~m along the coast and found the nearest one with
a k-d tree; this is within about 10~m of the exact distance. Walking
distances to the nearest supermarket and bus stop follow the road
network.

The second checks which area a home lies in (a point-in-polygon test).
We found the 2025 Statistical Area 2 (SA2) that contains each home, and
whether the home lies in a council flood plain or an aircraft noise
area.

The third looks up values for that area. Through its SA2, each home gets
the area's NZDep2023 deprivation decile (1 = least deprived, 10 = most),
2023 Census statistics and the number of new dwellings consented in the
past 12 months. Employment rate is employed people divided by people
aged 15 and over; unemployment rate is unemployed people divided by the
labour force; population density is the SA2 population divided by its
land area. Every sale found an SA2 and an NZDep2023 value. SA2 statistics are
area-level values shared by every home in the same SA2.

      supermarket, walking distance to bus stop \\
    Neighbourhood (6) & NZDep2023 decile, median personal income,
      employment rate, unemployment rate, population, population
      density (all per SA2) \\
    Hazards and building activity (3) & in flood plain, aircraft noise
      category, new dwellings consented in the SA2 (past 12 months) \\

  \end{tabular}
\end{table}

Land area, floor area and the two walking distances are right-skewed
(a few very large values), so we applied $\log(1+x)$ to them.

We also dropped two features that repeat others: sale quarter, which is
calculated from sale month, and the council's mass-appraisal floor area,
which repeats the building floor area (Spearman $\rho = 0.96$; variance
inflation factor 17--18). This cost XGBoost only \$212 of RMSE and stops
two copies of a feature from splitting its SHAP credit.

\subsection{Training and testing on time-based cross-validation folds}\label{sec:split}
House prices change over time, so a model should only learn from sales
that happened before the ones it predicts. Shuffling the data at random
would let the model learn from the future, which makes results look
better than they would be in practice~\cite{soltani2022}.

We therefore sort the 59,708 sales by date and use five-fold
expanding-window cross-validation (Fig.~\ref{fig:folds}). The data is cut
into six back-to-back time blocks of about 9,950 sales. In fold $k$, the
model trains on blocks $1$ to $k$ and is tested on block $k+1$, so each
fold learns from more history than the one before. Every sale after the
first block is tested exactly once, by a model that has never seen it.

Inside each fold, all preprocessing is learned from the training blocks
only and then applied to the test block: category codes (a category not
seen in training gets its own code), the median used to fill missing
walking distances (1.4--2.7\% of sales), and the price limits below.
Before training, we remove sales priced below the 1st or above the 99th
percentile of the training prices (\$430,000--\$450,000 and
\$4.2M--\$4.5M, depending on the fold), and apply the same limits to the
test block. This stops a few extreme sales from dominating the error,
but it means our results describe the middle 98\% of the market. After
this step, 48,777 test predictions remain across the five folds.

\begin{figure}[t]
  \centering
  \figph{../figures/timeseries_split.png}{3cm}{Expanding-window folds.}
  \caption{Five-fold expanding-window cross-validation. Each fold trains
  on all earlier sales and tests on the next period.}
  \label{fig:folds}
\end{figure}

For $n$ test sales with actual price $y_i$ and predicted price
$\hat{y}_i$, we report three error measures:
\begin{align}
  \mathrm{MAE}  &= \frac{1}{n}\sum_{i=1}^{n}\lvert y_i-\hat{y}_i\rvert,
  \label{eq:mae}\\
  \mathrm{RMSE} &= \sqrt{\frac{1}{n}\sum_{i=1}^{n}(y_i-\hat{y}_i)^2},
  \label{eq:rmse}\\
  \mathrm{MAPE} &= \frac{100}{n}\sum_{i=1}^{n}
                   \frac{\lvert y_i-\hat{y}_i\rvert}{y_i}.
  \label{eq:mape}
\end{align}
MAE is the typical error in dollars. RMSE gives more weight to large
errors, which matter most for expensive homes. MAPE is the error as a
percentage of price, so a \$100K miss on a \$600K home counts more than
the same miss on a \$3M home. We pool the test predictions from all five
folds and compute each measure once.

\subsection{Models}\label{sec:models}
Our main model is XGBoost~\cite{chen2016xgboost}, a gradient-boosted
tree model that predicts the sale price in dollars. We chose it because
it handles curved effects and mixed feature types well, and tree models
beat linear regression in earlier house price
studies~\cite{ceh2018,an2025}. It uses 500 trees, maximum depth 6,
learning rate 0.05, 80\% of rows and of features sampled per tree, and
random seed 42.

We do not tune any of our models. If each model were tuned separately,
part of any difference could come from tuning rather than from the
features or the algorithm. Fixed settings keep the comparisons fair, at
the cost of slightly understating what each model could reach.

To check that our results do not depend on one algorithm, we train three more machine learning models and a hedonic
regression on exactly the same inputs. The three machine learning models
are:
\begin{itemize}
  \item \textbf{Random forest}~\cite{breiman2001}: 150 trees, maximum
  depth 18, at least 2 sales per leaf.
  \item \textbf{CatBoost}~\cite{prokhorenkova2018}: 500 trees, depth 6,
  learning rate 0.05, set to match XGBoost. It gets the same integer
  category codes as the other models.
  \item \textbf{Neural network}: a multilayer perceptron with a learned
  embedding (up to 16 dimensions) for each categorical feature and three
  hidden layers (256, 128 and 64 units, ReLU, dropout 0.1), trained with
  Adam~\cite{kingma2015} (learning rate $10^{-3}$, batch 512, mean
  squared error) on the standardised log price. Training runs for up to
  100 epochs, but stops early once the error on the latest 10\% of the
  training period has not improved for 10 epochs; in practice this
  happened after 28--47 epochs. Numeric inputs are clipped to the training
  0.5th--99.5th percentiles and standardised.
\end{itemize}
The hedonic regression\label{sec:hedonic} is the traditional approach:
a linear regression on the log of price,
\begin{equation}
  \ln y_i = \beta_0 + \mathbf{x}_i^{\top}\boldsymbol{\beta}
            + \varepsilon_i,
  \label{eq:hedonic}
\end{equation}
fitted by ordinary least squares on the same 27 features. Each category
is one-hot encoded, with its most common level as the reference, and any
column that never changes in a fold's training data is dropped for that
fold. As for the neural network, numeric inputs are clipped to the
training 0.5th--99.5th percentiles, so one unusual value cannot produce
an extreme price. Turning a log prediction back into dollars with
$\exp(\cdot)$ underestimates the average price, so we multiply by
Duan's smearing factor~\cite{duan1983}:
\begin{equation}
  \hat{y}_i = \exp\!\left(\hat{\beta}_0 + \mathbf{x}_i^{\top}
  \hat{\boldsymbol{\beta}}\right)\cdot
  \frac{1}{m}\sum_{j=1}^{m}e^{\hat{\varepsilon}_j},
  \label{eq:smearing}
\end{equation}
where $\hat{\varepsilon}_j$ are the $m$ training residuals. The neural
network uses the same correction. For both models, final predictions
are capped to the range of training prices.

\subsection{Testing the hypotheses}\label{sec:tests}
We test H1 with a paired bootstrap. We train XGBoost on the baseline
and the augmented feature set over the same folds. To check that the
augmented
model is better and not just lucky, we draw $n$ test sales at random with
replacement and compute
\begin{equation}
  \Delta^{(b)} = M_{\text{base}}^{(b)} - M_{\text{aug}}^{(b)}
  \label{eq:bootstrap}
\end{equation}
for each metric $M$~\cite{efron1993}. Both models are scored on the same
resampled sales, so the test is paired. We repeat this $B=2{,}000$
times; the 2.5th and 97.5th percentiles of $\Delta^{(b)}$ give a 95\%
confidence interval. If it does not include zero, the improvement is
statistically significant.

We test H2 with a two-stage residual test. H1 shows that external
features help, but the model might only use them to relearn something
the property features already contain. In stage~1, we take the baseline
model's out-of-fold errors $r_i = y_i - \hat{y}_i^{\text{base}}$. In
stage~2, a new XGBoost model sees \emph{only} the 16 external features
and predicts $r_i$, with its own five-fold expanding-window split over
these sales in date order. The first block (8,132 sales) is training
only, leaving 40,645 sales with a stage-2 prediction. Stage~2 never sees
a property feature, so an out-of-fold $R^2$ above zero means the
external features explain something the property features missed.

We test H3 by comparing the five models on the same folds. All five
models of Section~\ref{sec:models} use the same features, folds, price
limits and metrics, so any difference comes from the model alone. We compare their
pooled errors and their errors in each fold. H3 is supported if every
machine learning model has a lower error than the hedonic regression,
both pooled and in each of the five folds.

\subsection{Measuring feature importance}\label{sec:attribution}
To see which external data drives the gain, we use fold~5: the model
trains on all sales up to January 2026 and is tested on the 9,769 sales
from January to August 2026. We study the three external groups of
Table~\ref{tab:features} with three methods. Grouped permutation
importance shuffles all features of a group together in the test set
and measures the RMSE increase (average of 20 repeats). SHAP gives the
share of a group in the total mean absolute SHAP value, on 500 test
sales. Drop-group retraining trains the model again without the group
(or without one feature) and measures the change in RMSE.

The three react differently when two groups carry similar information.
Permutation breaks a group while the model still relies on it, so it
shows how much the model \emph{uses} the group, which can overstate how
much it is \emph{needed}. Drop-group retraining lets the model fall back
on a similar group, so it shows what is \emph{unique} to the group but
can understate its value. SHAP splits the credit between similar
features. Reading them together shows both use and uniqueness.

\subsection{Explaining single predictions}\label{sec:explain}
SHAP values add up: for each sale, the model's average prediction plus
the SHAP value of every feature equals the prediction. We use this to
explain one held-out sale at a time. Starting from the average predicted
price, each feature adds or removes a dollar amount. For a short
summary, we add up the contributions within five themes: location,
neighbourhood and hazards (as in Table~\ref{tab:features}), house and
land (the size and building features), and market timing (sale year,
sale month and new dwellings consented). Adding them up is valid because
SHAP values are additive. A waterfall chart shows the largest single
contributions with feature values in real units (square metres,
kilometres, deciles). For the tree models we use exact
TreeSHAP~\cite{lundberg2017}; for the neural network and hedonic model
we use SHAP's permutation explainer with 100 training sales as
background.

\subsection{Online valuation benchmark}\label{sec:onlineval}
We initially explored homes.co.nz and OneRoof as possible sources of
property data, but did not use their data to train our final models.
To test the second half of RQ2, we compared our model with two free
automated estimates: HomesEstimate on homes.co.nz~\cite{homesnz} and the
OneRoof estimate~\cite{oneroof}. Online estimates are updated after a
sale, so an estimate looked up later may already reflect the sale price
and make the online tool look better than it was. We avoid this by using
estimates recorded in early July 2026 (homes.co.nz on 9 July, OneRoof in
the first days of July), before every sale in the sample.

We took the 50 most recent sales in our dataset (28 July to 18 August
2026), so each sold at least 19 days after its estimates were recorded.
Two
were outside the model's price limits (Section~\ref{sec:split}) and three
were missing at least one online estimate, leaving 45 homes with all
estimates. We compare two versions of our
XGBoost model on these homes. The first, ``Ours (to 24 Jan)'', is the
fold-5 prediction used in the rest of the paper, from a model trained
on sales up to 24 January 2026. The second, ``Ours (to 9 Jul)'', is the
same model retrained on the sales before 9 July 2026 (58,223 after the
same price limits), so that it knows the market up to about the same
time as the online estimates.
Besides MAE, RMSE and MAPE, we report the share of homes predicted within
5\% and 10\% of the sale price, a common way to judge automated
valuations.

\$131,040, from \$343,718 to \$212,678 (38.1\%), MAE by \$95,242, and
MAPE by 8.4 percentage points, from 19.3\% to 11.0\%. The paired
bootstrap gives 95\% confidence intervals of \$126,988--\$135,157 for the
RMSE gain, \$93,358--\$97,194 for MAE and 8.2--8.5 points for MAPE. None
includes zero, so \textbf{H1 is supported}. The gain is also steady over
time: the augmented model wins in every fold, with RMSE between
\$191,483 and \$238,373 against \$320,862 to \$370,069 for the baseline.
Both models also improve in later folds, which have more training
history.

This result shows that two homes with the same size, age and condition
can sell for very different prices depending on where they are, and the
baseline model, which only knows the house itself, cannot see this
difference.

\subsection{Impact of external features}
A model could look like it needs external data only because the property
features are not strong enough. Because of that, we ran the two-stage
test, and it rules this out. A model that sees
\emph{only} the 16 external features explains 29.3\% of the variance in
what the property-only model gets wrong (on 40,645 held-out errors),
and cuts the RMSE of those errors from \$339,582 to \$285,308. Since this
model never sees a property feature, the 29.3\% must be information the
property features do not contain, so \textbf{H2 is supported}. The other
70.7\% is not explained by our external data. It likely comes from things
neither data source records.

Location matters most on all three measures. Distance to the CBD alone holds 15.5\% of total SHAP, more than latitude (8.1\%) or
longitude (8.6\%), and is second only to building floor area (21.0\%)
across all 27 features (Fig.~\ref{fig:shap}). The SHAP plot shows the
shape of this effect: being close to the CBD raises the price a lot,
while beyond a certain distance further kilometres change little. A
straight-line model cannot capture this shape.

Neighbourhood statistics, on the other hand, mostly repeat location.
The model clearly uses them: shuffling the group raises RMSE by 32.1\%, and it
holds 16.1\% of SHAP, led by the deprivation decile (6.9\%). Yet
retraining without the group costs only \$1,665, because the model
recovers almost the same information from location. The reverse is not
true: without the location group the model still loses \$20,146, even
though the neighbourhood statistics remain. Without all external
features it loses \$129,379, more than six times the sum of the three
group losses in Table~\ref{tab:attribution}. In plain terms, location and neighbourhood
statistics describe much the same thing (how desirable an area is), and
location describes it more fully. The same holds for single features: no
external feature costs more than \$3,752 when dropped alone (latitude),
and for eight of them the model is slightly better without them, within
noise. This is why one ranking method on its own would mislead.

Hazards and building activity add almost nothing at city scale. Only
6.4\% of sales lie in a flood plain and 5.3\% in an aircraft
noise area. These features may matter for those homes, but they cannot
explain much of the price variation across all of Auckland. Our hazard
data is also simple: it only records whether a home is in a flood plain
and which noise category applies. With better hazard data, such as flood
depth or records of past flooding, hazards may contribute more. The
12-month count of consents in an SA2 changes slowly and overlaps with
location.

\subsection{Accuracy versus interpretability}\label{sec:res-hedonic}
The hedonic model's strength is that each coefficient has a one-sentence
meaning that holds for every house. On fold~5, for example, each extra
\$10,000 of median personal income in the SA2 goes with 12.3\% higher
prices, each kilometre further from the CBD with 1.2\% lower prices, each
step up the deprivation decile with 1.3\% lower prices, and a flood
plain location with 1.8\% lower prices, all else equal. XGBoost cannot
give one number per feature, because a feature's effect changes from
sale to sale. Instead, SHAP gives a dollar breakdown for each
prediction. This is the trade-off RQ2 asks about: the machine learning
model gives up one global number per feature, but keeps a clear per-sale
explanation while cutting the hedonic model's MAPE by about 30\%.

Fig.~\ref{fig:house}\label{sec:res-explain} shows what such a per-sale
explanation looks like for one held-out sale from fold~5's test period:
a home sold in June 2026 for \$1,285,000. The XGBoost model,
trained only on sales up to January 2026, predicted \$1,266,131 (1.5\%
below). Starting from the average prediction of \$1,151,033:
\begin{itemize}
  \item the \emph{neighbourhood} adds \$65,399, mostly from a low
  deprivation decile (2 of 10, +\$71,055);
  \item \emph{location} adds \$41,119: the home's latitude (+\$85,033)
  outweighs its 16.9~km distance from the CBD ($-$\$63,763);
  \item the \emph{house and land} add \$26,184: a large floor area
  (172~m\textsuperscript{2}, +\$84,080) and a new building (built in the
  2020s, about +\$34,000) more than offset a small section
  (186~m\textsuperscript{2}, $-$\$94,139);
  \item \emph{market timing} (a 2026 sale) removes \$19,070, and
  \emph{hazards} change the price by only \$1,469.
\end{itemize}
With this breakdown, a buyer can see that the price is pushed up mainly by the
area and by the large, new house, while the small section pulls it
down.

\subsection{Additional analyses}\label{sec:res-additional}
Besides testing our main research questions, we also wanted to apply
what we learned in COMPSCI 760 to explore two additional areas:
prediction reliability and time-series forecasting. For prediction
reliability, we examined whether our model tended to overestimate or
underestimate properties in different price ranges. For time-series
forecasting, we used historical sales data to predict Auckland's monthly
median house price. These experiments helped us understand other
aspects of house price prediction that were not fully covered by our
main model comparisons.

\subsubsection{Fairness and prediction reliability}
Although our models achieved good overall accuracy, we also wanted to
see whether their predictions were equally reliable for different types
of properties. We therefore carried out a separate analysis using
Random Forest and LightGBM~\cite{ke2017lightgbm} to examine prediction
errors across different sale-price ranges. These models were trained
using an earlier version of our dataset, so their results are reported
separately from the main model comparison.

As shown in Fig.~\ref{fig:rel-mae}, both models made larger errors in
dollar terms for more expensive properties. For example, LightGBM's mean
absolute error (MAE) increased from \$91,886 for properties sold below
\$750,000 to \$400,321 for properties sold at \$2 million or more. This
suggests that the models had more difficulty predicting the prices of
expensive properties, although larger dollar errors do not necessarily
mean larger percentage errors.

\begin{figure}[t]
  \centering
  \figph{../figures/reliability_mae_by_price_band.png}{3.2cm}{MAE by
  sale-price band.}
  \caption{Mean absolute error by observed sale-price band for
  separately trained Random Forest and LightGBM models.}
  \label{fig:rel-mae}
\end{figure}

We also examined whether the models tended to predict prices above or
below the actual sale prices. Fig.~\ref{fig:rel-bias} shows that both
Random Forest and LightGBM generally overestimated lower-priced
properties and underestimated more expensive ones. This pattern is
consistent with predictions being drawn towards the middle of the price
distribution.

\begin{figure}[t]
  \centering
  \figph{../figures/reliability_bias_by_price_band.png}{3.2cm}{Signed
  error by sale-price band.}
  \caption{Mean signed prediction error (predicted minus actual) by
  observed sale-price band for separately trained Random Forest and
  LightGBM models. Positive values indicate overestimation, while
  negative values indicate underestimation.}
  \label{fig:rel-bias}
\end{figure}

These findings show why overall accuracy alone is not enough to assess
prediction reliability. A model may achieve a relatively low average
error while still making larger or more systematic errors for certain
property groups. In this analysis, fairness refers to differences in
prediction reliability across observable property groups. We do not draw
conclusions about discrimination against demographic groups, as our data
does not support that assessment.

\subsubsection{Time series forecasting}
Besides predicting individual property prices, we also wanted to
investigate whether historical sales data could help us forecast changes
in Auckland's housing market. For this separate experiment, we used an
earlier version of our eligible sales dataset and calculated monthly
median sale prices from 59,281 transactions between January 2024 and
June 2026. We excluded July and August 2026 because the available
records for those months were incomplete. Unlike our main property-price
prediction experiments, this analysis focused on forecasting monthly
market prices rather than the sale price of individual homes.

We compared eight forecasting methods, including previous-month and
seasonal-naive forecasts, exponential smoothing and ARIMA-based
approaches~\cite{hyndman2021fpp}. The 30-month series was divided
chronologically into 18 training months, six validation months and six
test months, as shown in Fig.~\ref{fig:ts-series}. We used the
validation period to select the best-performing method before
evaluating it on the final test period.

\begin{figure}[t]
  \centering
  \figph{../figures/forecast_monthly_median.png}{3.2cm}{Monthly median
  sale prices.}
  \caption{Recorded monthly median sale prices from the earlier
  eligible-sales dataset, with the six-month validation and test periods
  shaded.}
  \label{fig:ts-series}
\end{figure}

Seasonal Naive achieved the lowest validation mean absolute error (MAE)
of \$6,625. This method predicts each month's median sale price using
the value from the same month in the previous year. As shown in
Fig.~\ref{fig:ts-forecast}, it achieved an MAE of \$9,500 and an RMSE of
approximately \$13,054 during the six-month test period from January to
June 2026.

\begin{figure}[t]
  \centering
  \figph{../figures/forecast_seasonal_naive.png}{3.2cm}{Seasonal Naive
  forecasts.}
  \caption{Actual monthly median sale prices compared with Seasonal
  Naive forecasts over the six-month test period.}
  \label{fig:ts-forecast}
\end{figure}

We also tested whether historical market information could improve
individual property-price predictions. In a separate Random Forest
experiment using an earlier modelling setup, we added past monthly
median prices, rolling statistics and transaction counts. The test MAE
increased slightly from \$160,489 to \$161,496, suggesting that these
features did not improve that particular model. These results are not
directly comparable with the Random Forest results reported in our main
model comparison.

These findings suggest that historical price information can be useful
for forecasting monthly market prices without necessarily improving
individual property predictions. However, our forecasting experiment
covered only 30 months, with six months available for final testing.
Also, monthly median sale prices depend on which properties were sold
during each month, so they do not necessarily reflect changes in the
value of a typical home. A longer historical dataset would help us
assess how well these methods perform under different market conditions.

\section{Limitations}\label{sec:limits}
First, our results cover only part of the market. Because the price
filter keeps the middle 98\% of each fold's training prices, the results
describe the typical Auckland home and may not hold for the cheapest or
most expensive 1\% of sales. In addition, record linkage placed 97.6\%
of the arm's-length single-home sales. If the missing 2.4\% are
different from the rest, for example new subdivisions not yet in LINZ,
our results could be slightly off for that part of the market. The data
also covers only one city over 2024--2026, when the market was flat: the
median sale price stayed between \$950,000 and \$1,020,000 in every
quarter. Since tree models cannot extend a price trend into months they
have not seen, their predictions would lag in a fast-rising market, and
the size of the gain may differ in other cities or periods.

Second, the area data is coarse. The neighbourhood features are 2023
Census and NZDep2023 values for the whole SA2, so every home in an SA2
shares them. They also do not change over 2024--2026, and they describe
the area rather than the buyer. Moreover, one SA2 (51 sales) has a
recorded median income of \$0, probably a census coding issue that we
did not correct.

Third, our explanations show what the model relies on, not what causes
prices to change. Because location and neighbourhood features overlap,
no single importance number should be read as the true value of one
feature.

Fourth, we fixed every model's settings to keep the comparisons fair.
This means that a project that only cared about accuracy could tune each
model and would likely do somewhat better than every number here.

Fifth, our additional analyses have some limitations. The prediction
reliability experiments used earlier versions of our dataset and
separately trained models, so their findings cannot be directly applied
to the final XGBoost model. The time-series forecasting experiment
covered only 30 months, with six months used for final testing. A longer
historical dataset would help us understand whether the forecasting
results remain reliable under different market conditions.

Lastly, the online benchmark is small. It uses 45 homes from three
weeks of sales, mostly in the middle of the market, and two online
tools. Therefore, while the direction of the result is clear, the exact
size of the gap is uncertain, and other tools (such as
propertyvalue.co.nz) may score differently.

\section{Conclusion and Future Work}\label{sec:conclusion}
This paper asked whether Auckland-specific external data improves house
price prediction (RQ1), and how an explainable model built on it compares
with a traditional hedonic model and free online valuations (RQ2). We
built a pipeline from the Auckland Council sales file to a linked
dataset: Splink record linkage gave 95.5\% of properties a LINZ
coordinate, and the coordinate let us attach 16 external features from
nine public sources. We then tested the models with time-ordered cross-validation,
so every prediction was made from past sales only.

For RQ1, the answer is yes, by a wide and significant margin. Adding the
external features cuts XGBoost's RMSE by 38.1\% and MAPE from 19.3\% to
11.0\% (H1), and a model that sees only external data explains 29.3\% of
the variance in the errors a property-only model leaves (H2). The reason
is simple: two similar houses in different places can sell for very
different prices, and only the external features tell the model where a
house is and what its area is like.

For the first part of RQ2, all four machine learning models beat a
hedonic regression on the same features (H3), most likely because they
can learn curved and local effects. XGBoost is the most accurate (MAPE
11.0\% vs 15.7\%), and it still explains each prediction in dollars
through SHAP. For the second part of RQ2, two free online estimates
(homes.co.nz and OneRoof) recorded before each sale were more accurate
on 45 recent sales (MAPE 5.8\% for both vs 9.6\%), even after we
retrained our model up to the same date. Public council and area data
bring our model within about 4 MAPE points of commercial estimates;
closing the rest seems to need richer data about the house itself.
Even so, our model offers something the online tools do not: for each
price, a SHAP waterfall chart (Fig.~\ref{fig:house}) shows which features
raised or lowered it and by how much, so a buyer can see why a home is
valued as it is. A buyer could use the two together, taking the online
estimate as the number and our explanation as the reason behind it.

The clearest practical finding is that most of the value of external
data is the value of \emph{location}. Distance to the CBD and the
coordinates carry the largest share; area census and deprivation
statistics are useful but mostly repeat what location already says; and
flood, noise and building-activity features add almost nothing to a
city-wide model. For a team building a similar model with limited time,
an accurate coordinate (here, good record linkage) and a few location
measures are worth more than many extra area features.

Our additional experiments also highlighted two other aspects of house
price prediction. The prediction reliability analysis showed that errors
were not evenly distributed across property price ranges, with larger
errors and more frequent underestimation for expensive properties. The
time-series forecasting experiment showed that a simple seasonal-naive
method could produce reasonably accurate monthly median price forecasts
over the six-month test period. These findings suggest that evaluating
property prices requires looking beyond overall model accuracy, although
further testing would be needed to confirm the results.

The main drawbacks are that the model is less accurate than commercial
online estimates and misses most on unusual homes, that area
data is coarse and fixed in time, and that SHAP shows association, not
cause. If this work continued as a master's project, we
would: (1) repeat the online benchmark on a larger sample and several
tools, recording estimates for homes as they are listed, and test
whether listing data (photos, descriptions) closes the gap; (2) tune
each model and add a prediction interval (for example with quantile regression or
conformal prediction), so the buyer sees a price range instead of one
fixed price;
(3) test whether hazards matter more in the parts of Auckland where they
are common, using location--feature interaction methods such as
GeoShapley~\cite{li2024geoshapley}; and (4) add school enrolment zones
and recent nearby sales, built only from earlier
sales~\cite{soltani2022}.
